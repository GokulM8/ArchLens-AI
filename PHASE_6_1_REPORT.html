Configuration

Phase 6.1 uses environment variables for configuration:

Variable Description Example
ARCHLENS_LLM_PROVIDER Provider name (openai, mock) openai
ARCHLENS_LLM_MODEL Model identifier gpt-4o
ARCHLENS_LLM_API_KEY API authentication key sk-proj-...
ARCHLENS_LLM_BASE_URL API endpoint (optional) https://api.openai.com/v1
ARCHLENS_LLM_TIMEOUT Request timeout in seconds 30

Key Design Principles

  • Vendor-agnostic abstraction — Easy to add new providers
  • Environment variable configuration — No hardcoded secrets
  • Async from the start — Production-ready concurrency
  • Graceful degradation — Works without LLM configuration
  • Mock provider for testing — CI doesn't need external APIs
  • Type-safe responses — Pydantic data models
  • No secrets in errors — Safe logging and reporting
  • Deterministic factory — Consistent behavior across invocations

Usage Example

from app.llm.factory import LLMProviderFactory from app.llm.provider import LLMRequest # Check if LLM is configured if LLMProviderFactory.is_configured(): provider = LLMProviderFactory.create_provider() request = LLMRequest( system_prompt="You are an architecture expert", user_prompt="Explain this architecture", context={"repository": "my-app"} ) response = await provider.generate(request) print(response.content) else: print(LLMProviderFactory.get_configuration_error())

Implementation Details

Provider Interface

All providers implement the LLMProvider abstract class:

  • validate_config() — Check if provider is properly configured
  • get_config_error() — Return user-friendly error message if invalid
  • generate(request) — Async method that returns LLMResponse

Factory Pattern

The LLMProviderFactory handles:

  • Reading configuration from environment variables
  • Creating appropriate provider instance
  • Validation of configuration completeness
  • Graceful error messages

OpenAI Provider

Production-ready implementation:

  • Uses httpx.AsyncClient for async HTTP
  • Handles request/response serialization
  • Implements timeout and error handling
  • Returns structured response with metadata

Mock Provider

Testing without external dependencies:

  • Always available, no configuration needed
  • Deterministic responses based on input hash
  • Includes usage metadata for compatibility
  • Fast responses for test execution
